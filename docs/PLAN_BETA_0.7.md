# PLAN_BETA_0.7.md — План сшивания мира до Beta-0.7

> Цель: планомерное развитие персонажа + верный вектор его историй в дневнике.
> Метод: **1 фаза = 1 тест** — фаза считается готовой только после автотестов + живой верификации (логи/Playwright) и подтверждения заказчиком.
> Решения заказчика: очистка **всё подчистую** (включая админа), порядок **Мир → Мозг → Дневник**, дневник **главы + мотивы решений**, темп **средний** (×2–3 медленнее текущего).

## Definition of Done (Beta-0.7)

1. Чистая база: ни одного тестового пользователя/героя, админ пересоздан, мир стартует с дня 1.
2. Мир влияет на действия: дождь → клёв, плотность → засады, затмение → кражи (мёртвых контрактов нет).
3. Мозг — единое ядро: одна точка оценки целей с трассировкой «почему», мировые события меняют решения по характеру.
4. Дневник — читаемая биография: главы по дням/событиям, у решений виден мотив, мир присылает «новости» героям в регионе.
5. Прогрессия среднего темпа: уровень ≈ раз в 2–3 игровых дня, скиллы растут ощутимо, но не мгновенно.
6. `mix test` зелёный, `npm run build` чистый, консоль браузера без ошибок.

## S-0. Чистый старт (очистка + пересоздание) — ✅ ВЫПОЛНЕНА (2026-09-02, тест S-0-T зелёный)

**Объём:**
- TRUNCATE (CASCADE): `users, heroes, journal_entries, pets, inventory_items, equipment, active_quests, reputation(s), suggestions, world_events`.
- Сброс мира: удалить `world_state` (key="snapshot") → после рестарта Kernel инициализирует день 1 без героев.
- Не трогаем: `items, locations, monsters, quests, narrative_templates (system), game_configs` — это фундамент мира.
- Пересоздать админ-аккаунт (register + is_admin=true через SQL).
- Дым: register → create hero → 1 тик → первые записи журнала.

**Тест фазы (S-0-T):** свежий аккаунт создаёт героя, первый тик пишет «первые шаги» в дневник, снапшот мира = день 1, вход админом работает, мир тикает (tick 2+).

## S-1. Мир → Действия (закрыть мёртвые контракты) — ✅ ВЫПОЛНЕНА (2026-09-03, тест S-1-T зелёный: 65/65)

**Бонус-фикс S-1:** schemaless-select `world_locations/0` отдавал raw UUID binary → binary в `location_id` события ронял Jason при персисте снапшота (Kernel crash-loop при спавне событий). Исправлено типизированным schema-запросом.

**Объём:**
- `FishingAction` потребляет `ctx.weather` через `Weather.fishing_bonus/1` (дождь +30%, гроза +15%).
- `ExploreAction` — шанс засады × `Migration.encounter_factor(density)` из `ctx.world["density"]`.
- `StealingAction` — бонус при активном затмении (`Events.eclipse_active?/1`), штраф при ярмарке (толпа).
- Числа — в `game_configs` (`activities`), не в коде.

**Тест фазы (S-1-T):** статистические тесты с сидом (дождь ловит больше, плотность 2.0 → засады чаще, затмение → кражи удачнее) + живой прогон: форс-событие затмения через админку → в журнале вора виден эффект.
**Результат:** 65/65 тестов (×4 прогонов, стабильно) — точные тесты клёва (0.45→0.75 при дожде; легаси-погода локации игнорируется), статистика засад (плотность 2.0 vs 0.5), статистика воровства (затмение −поимки, ярмарка +стража). Живой прогон: затмение через админку → плашка 🌑 с TTL, событие персистится с UUID-строкой, 0 крэшей Kernel, герой тикает (8 записей журнала), `npm run build` чистый.

## S-2. Brain.Intent — единое ядро решений — ✅ ВЫПОЛНЕНА (2026-09-03, тест S-2-T зелёный: 72/72)

**Реализовано:** `Brain.Intent.evaluate/1` — три стадии оценки (base_goals → Graph.enrich → world_stage), `Goal.best` делегирует. Мир влияет по характеру, но не решает: отброшенные цели не воскрешаются. Правила модификаторов (кэп `world_limits.utility_cap` ±0.15): дракон (осторожные прячутся, храбрые ищут боя), волна монстров рядом, война в регионе (осторожные не путешествуют, жадные ждут цен), ярмарка в городе (+shop/+socialize), затмение (+steal/+break_in), гроза/ливень (−travel осторожным, +rest). `decision_log` получил блок `world` (погода/события/войны) — путь к мотивам в дневнике (S-3).

**Попутно вскрыты и починены 3 критических бага FSM/pipeline (Фазы 0):**
1. `resolve_combat` возвращал **весь** старый state_data как «дельту» → merge затирал advance_plan и decision_log → герой вечно переигрывал шаг Fight одного плана (3 игровых дня!), решения не принимались. Теперь дельта `{"combat" => nil}`.
2. FSM не шагал план после боя (`Map.delete(combat)` без advance_plan) → добавлен advance.
3. Pipeline терял state_data при nil-результате FSM (мгновенный первый шаг плана) — план+лог не сохранялись. Добавлен `save_state_data` в else-ветке.

**Тест S-2-T:** 5 чистых (дракон×осторожный с трассировкой, ярмарка×shop, война×travel, гроза×rest, затмение не воскрешает вора вне города) + integration (храбрый vs осторожный при живом монстре: fight выше у храброго на ≥0.05) + decision_log с world-контекстом. Живой прогон: лог растёт (16 записей), цели разнообразны, каждая запись видит мир (dragon/monster_wave/war/weather).

**Объём:**
- Новый `game/brain/intent.ex`: единственная точка оценки 14 целей из `{needs, personality, quirks, links, world, weather, memories}` → `{best, trace}`.
- `Goal.best` делегирует в Intent; `eval_*` становятся чистыми хелперами.
- **Мировые модификаторы решений** (по характеру): война/дракон в регионе → осторожные избегают travel/fight, храбрые наоборот; ярмарка → shop/socialize; затмение → steal у импульсивных; гроза → осторожные не путешествуют.
- `decision_log` обогащается: `{tick, day, goal, top3: [{goal, score, reasons[]}], world_context}`.

**Тест фазы (S-2-T):** осторожный герой при драконе в регионе — utility travel ниже, трассировка содержит причину; бравый — наоборот. Живой прогон: decision_log в Analytics/тултипах показывает «почему».

## S-3. Дневник: главы + мотивы решений — ✅ ВЫПОЛНЕНА (2026-09-03, тест S-3-T зелёный: 85/85)

**Реализовано:** `Journal.Chapters` (чистые функции): границы глав — смена дня ИЛИ перелом (война/дракон/затмение/волна — по новым событиям из `break_seen`; арест; уровень). Заголовок «День N. <фраза>» — фразы в `game_configs["journal"].titles`. Мотив решения (S-2 трасса) пишется в `journal_entries.motive` только при создании плана (цель изменилась). «Новости мира» (`world_news`) — при активном не-виденном событии в мире героя с шансом `news_chance`, текст из `narrative_templates` (seed_phase2), `news_seen`-ротация 20.

**Инфраструктура:** миграция (chapter/chapter_title/motive, идемпотентная), schema, JournalController API, HeroChannel push, конфиг `journal` (defaults в ContextBuilder + dev-БД). Фронт: группировка журнала по главам (DashboardPage JournalPanel + components/journal/JournalPanel), заголовки глав, мотивы курсивом, 📡 для новостей; легаси-записи (без главы) без заголовка.

**Тест S-3-T:** 13 unit-тестов Chapters (день/дракон/повтор/чужая-локация/арест/уровень/мотивы/новости) + полный прогон 85/85. Живая проверка (Playwright): главы группируются, перелом monster_wave открыл «День 11. Нечисть выходит из пустошей» посреди дня, мотив «Решение: complete_quest (0.893) — greed×dexterity…», новость «Слухи по дорогам: Дракон».

**Объём:**
- Backend: `journal_entries.chapter` (граница главы = новый игровой день ИЛИ событие-перелом: война в регионе, уровень, арест, дракон); заголовок главы «День N. <Название по перелому>».
- Мотив решения — в запись журнала (из трассировки S-2), курсивом перед действием.
- «Новости мира»: hero в регионе события получает ambient-запись (война началась, дракон замечен, ярмарка открылась) — вектор истории задаёт мир.
- Frontend: группировка журнала по главам (липкая шапка «День N»), inline мотивы.

**Тест фазы (S-3-T):** Playwright — главы видны, мотив читается, после объявления войны (админ-форс) у героев региона появляется новость, глава открывается.

## S-4. Прогрессия: средний темп (×2–3 медленнее) — ✅ ВЫПОЛНЕНА (2026-09-03, тест S-4-T зелёный: 93/93)

**Реализовано:** `Pipeline.apply_progression/2` (публичная чистая функция, применяется в начале apply_result): `xp_multiplier` ×0.5, `gold_multiplier` ×0.75 (только награды — траты не режутся), `Skills.gain/4` + `Skills.rate/1` — навыки ×0.5 во всех 4 активностях. Порог уровня уже рос ×1.5 (`leveling.xp_multiplier`) — не тронут. Конфиг `progression` — dev-БД + defaults в ContextBuilder (пустой конфиг → старый темп).

**Тест S-4-T:** 5 юнитов apply_progression (xp, золото+, траты-не-масштабируются, пустой конфиг, нули) + 3 Skills (rate из конфига, gain×0.5) + A/B-симуляция 200 наград (XP 4000→2000 = ×2 медленнее, золото 2400→1800 ×1.33 мягче). Живой замер: XP/час героя 1182 → **573** (0.48× — точно ÷2).

**Объём:**
- Кривые в конфиге `progression`: XP-награды ÷2, `xp_to_next` ×1.5, рост скиллов ×0.5, золото наград −25% (цены без изменений) — уровень ≈ 2–3 игровых дня.
- Сверка, что arrest/лечебные расходы не делают героя банкротом на ранних уровнях.

**Тест фазы (S-4-T):** интеграционная симуляция 200 тиков (сид) — герой достигает ожидаемого уровня/золота/скиллов, дневник разнообразен (нет монокультуры одной активности).

## Правила полирования (действуют во всех фазах)

- Новая возможность мира не считается готовой, пока не потреблена действием/оценкой цели (урок мёртвых контрактов).
- Числа — только в `game_configs` (дефолты в ContextBuilder + значения в dev-БД).
- state_data — единственный писатель (AGENTS.md 2.1).
- Каждая фаза: код → автотесты → живая верификация → отчёт → подтверждение заказчика → следующая фаза.
