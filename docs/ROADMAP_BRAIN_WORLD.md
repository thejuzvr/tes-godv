## Часть I. Мозг героя (BrainHash)

### I.1. Концепция

Каждый герой получает **детерминированный геном личности** — «паспорт мозга»:

```
brain_hash = SHA256(user_id || hero_ordinal)   # hex, хранится в heroes.brain_hash
```

> **Правило (решено):** 1 новый пользователь = 1 новый герой. Герой фактически не умирает — он **перерождается**: hash мозга постоянен на всю жизнь, реинкарнация меняет только поколение.

Из hash детерминированно (seedable PRNG) выводится:

1. **Базовые черты** (сейчас `Enum.random(30..70)` — невоспроизводимо; станет: тот же user + тот же номер героя = тот же мозг).
2. **Микро-связи (нейронный слой)** — взвешенный граф между чертами: `bravery×greed → риск-аппетит`, `curiosity×caution → осторожное исследование`, `empathy×sociability → привязанность к питомцу`… ~15 связей, вес −1.0…+1.0 из hash.
3. **Архетип** — Sims-подобная «личина»: выводится из профиля черт (не хранится, вычисляется): «Осторожный скупец», «Безрассудный романтик», «Набожный искатель» (12 архетипов).
4. **0–2 причуды (quirks)**: «боится воды», «собирает чашки», «рыбачит на рассвете» — влияют на выбор целей и добавляют флейвор в журнал.

### I.2. Мозг живой: пластичность и эволюция

Сейчас черты заморожены. Вводим **три механизма жизни**:

| Механизм | Правило | Ограничитель |
|---|---|---|
| Пластичность черт | События сдвигают черту на ±0.5…2 (смерть от орка → caution +2) | Бюджет: 10 п. суммарно за 7 игровых дней; возврат к базе 0.2/день |
| Дрейф связей | Успех по связке усиливает вес (+0.01), провал ослабляет (−0.015) | Коридор ±0.3 от стартового веса из hash |
| Реинкарнация | Смерть → перерождение: `generation += 1`, черты наследуются с мутацией ±5, hash мозга неизменен | «Эволюция личности»: переродившийся помнит прошлую жизнь, но не равен ей |

Хранение (JSONB `heroes.personality`, расширение):

```json
{
  "traits":   {"bravery": 62, "curiosity": 41, "greed": 55, "sociability": 48,
               "tenacity": 70, "caution": 33, "patience": 58, "dexterity": 44,
               "empathy": 61},
  "links":    {"bravery~greed": 0.35, "curiosity~caution": -0.20, "...": 0.0},
  "quirks":   ["collects_cups"],
  "archetype_hint": "wanderer",
  "plasticity_budget": {"week": 3, "spent": 1.5},
  "generation": 1,
  "decision_log": []           // последние 50 решений с reason-trace
}
```

Новые черты: **patience** (рыбалка/собирательство), **dexterity** (воровство/проникновение/побег), **empathy** (питомцы/NPC). Итого 9.

### I.3. Utility AI v2 — решения через связи

Единая точка — `Brain.evaluate(goal, ctx)` (новый модуль `lib/tes_idle/game/brain/`):

```
utility = базовая нужда                                    (как сейчас)
         + Σ(trait × link × context_factor)                (микро-мозг)
         + world_modifier(goal, ctx.world)                 (ядро мира, Часть II)
```

Каждое решение пишет reason-trace в `state_data.decision_log`:
`{"goal": "fish", "scores": {...}, "top_reasons": ["patience 58 × link fish_calm 0.4", "weather rain +0.08"], "day": 12}` — это сырьё для страницы «Аналитика».

**Feature flag** в `game_configs`: `"brain_v2": true|false` — откат одним ключом.

## Часть III. Ядро мира (World Kernel) — ✅ ЯДРО ЗАПУЩЕНО (2026-09-02, W-0…W-7)

### III.1. Концепция

Отдельный **`WorldKernel`** — одиночный GenServer (`name: __MODULE__`) со своим тиком (60с, не связан с 30с героев). Единственный писатель `world_state`; герои только читают снапшот через ContextBuilder.

**Реализация**: снапшот живёт в ETS (`:world_snapshot`, атомарное чтение) + персистится в `world_state` (key="snapshot"); модули `lib/tes_idle/world/{kernel,snapshot,weather,economy,migration,factions,events,aggregator}.ex`. Сид randomness — :rand (детерминизм по seed — задел).

```
WorldKernel.tick()
  → WeatherSystem.step()      # марковские цепи по регионам
  → EconomySystem.step()      # цены: дрейф к базису + применённая нагрузка
  → MigrationSystem.step()    # переток монстров между локациями
  → FactionSystem.step()      # войны/стычки/мир
  → EventSystem.step()        # мировые события с TTL
  → persist world_state + PubSub.broadcast("world:lobby", {:world_update, snapshot})
```

| Система | Состояние | Влияние на героя |
|---|---|---|
| **Погода** | per-region (region = поле у location): clear/cloud/rain/storm/snow | travel ±скорость, fishing +, mood −, hunger зимой быстрее (эффекты уже читает ContextBuilder — расширить) |
| **Экономика** | `prices[city][category]` множители 0.6–1.8 | ShopAction берёт множитель из ctx.world; война ×1.5 в вовлечённых городах |
| **Миграции монстров** | `density[location_id]` | FightAction выбирает монстра по локальной плотности: редкие — реально редкие; «волна» миграции = мировое событие |
| **Фракции/войны** | Фракции по лору (Империя, Братья Бури, автономные); `relations[a,b]` −100…100; **состав фракций динамический — город может внезапно переметнуться к другой**; war_zone список | utility боёв ±, цены, новые квесты-типы, заголовочные нарративы |
| **События** | `events[]` c TTL (Дракон над Ривервудом 24ч, Ярмарка −20% цен, Затмение…) | вероятностный спавн + ручной запуск админом |

### III.2. Синхронизация и веса («персонаж не ломается»)

1. **Пределы влияния** — жёстко в `game_configs` (`"world_limits"`): utility-модификатор цели ±0.15 max, цены ±50%, шанс встреч ±30%. Ядро мира меняет *вероятности*, но никогда не блокирует базовый цикл.
2. **Обратное влияние через агрегатор**: герои не пишут в world_state напрямую. `WorldAggregator` (аналог ActivityFlushWorker) копит события тиков (kills/purchases/thefts по локациям) и раз в 5 минут применяет с масштабом `sqrt(n_heroes)` — один герой экономику не сдвинет, сотня — сдвинет.
3. **Детерминизм**: все случайности ядра сидируются `(world_day, cluster_node)` — реплей и отладка.
4. **Консистентность планов**: FSM-героя не ломается при смене мира — существующий механизм (state недоступен → план сбрасывается в idle → пересчёт) уже покрывает; снапшот читается атомарно одним `GET`-запросом (ETS + persisted row).
5. **Фронтир синхронизации**: `game_hour` героев и `world_day` связаны формулой (единая шкала игровых суток), рассинхрон исключён конструктивно.

## Часть IV. Нарративы масштабных событий («сцены»)

Двухуровневая система:

1. **Сцены (жёстко прописанные)** — новый `kind="scene"` у `narrative_templates`:
   - длинные структурные тексты (завязка → развитие → кульминация) для мировых/жизненных событий: `scene_war_declared`, `scene_war_ended`, `scene_dragon_event`, `scene_fair_open/close`, `scene_arrest`, `scene_pet_adoption`, `scene_hero_death`, `scene_level_milestone`;
   - 1–3 канонических текста на сцену, переменные (`{city_a}, {city_b}, {days}, {hero_name}, {monster_name}`) — «общая картина случая», персонализация — вторична;
   - в журнале — отдельный визуальный стиль (kind=scene → карточка-«глава» с иконкой, по VISUAL_RULES).
2. **Линт переменных** (закрывает класс багов «исследует city» / «Здесь мог быть ваш мем»):
   - канонический список переменных по типам (источник истины — модуль `Narrative.Vars` в backend, тот же список в модалке-Словнике);
   - при импорте/аппруве шаблона: неизвестная переменная или переменная не из набора типа → отказ с пояснением;
   - тест-контракт: любой активный шаблон из БД форматится без «сырых» enum-утечек (глоссарий-тест).

## Риски и решения

| Риск | Решение |
|---|---|
| Один GameTickWorker не потянет мир + 100 героев | W-0 впереди включения ядра; тик мира независим |
| Brain v2 меняет баланс непредсказуемо | Feature flag + симуляции на ботах до включения всем |
| Гонки записи world_state | Единственный писатель — WorldKernel; герои читают снапшот |
| Bloat `state_data` | Ротация decision_log (50) и memories (20); ledger'ы — в отдельные таблицы |
| Обратная совместимость героев | Все новые поля nullable/default; черты существующих героев не трогаем |
| Сломанные шаблоны при росте числа типов | Линт N-2 до массового добавления текстов |

## Принятые решения (2026-09-02)

1. **Мозг**: 1 новый пользователь = 1 новый герой; герой не умирает, а **перерождается** — hash мозга постоянен, реинкарнация = новое поколение с наследованием черт (мутация ±5) и сохранением связей.
2. **Аналитика**: приватна — видит только владелец; кнопка «Поделиться» генерирует сводную карточку для соцсетей (конверсия и внимание). hash — полуоткрытый идентификатор: пересечения мозгов минимальны, секретности не требует.
3. **Питомцы**: питомец может погибнуть — тогда уходит в **cooldown с возрождением по таймеру: 4 реальных часа** (конфигурируемо в game_configs, `revive_at` по серверному времени).
4. **Войны**: между **лор-фракциями**; в состав фракции входят города (их может быть больше одного), и город может внезапно **переметнуться** к другой фракции — часть живой симуляции мира.

### Решения по механикам (2026-09-02, вторая волна)

5. **Розыск**: bounty **per-city** (`state_data.bounty`), репутация — **per-faction** (существующая схема `reputations`); стража проверяет bounty города при входе (порог 50 → плати/беги); jail: отсидеть (bounty/50 тиков) / взятка (2×bounty) / побег (dexterity vs guard_level, провал = bounty ×1.5 + конфискация краденого).
6. **Питомцы**: при лояльности 0 питомец уходит **навсегда** (возможна ротация, если герой забросил уход); гибель → cooldown 4ч → возрождение (loyalty −20, mood героя −10).
7. **Причуды v1** — фиксированный набор из 8: боится воды, рыбак на рассвете, коллекционирует чашки, ночной вор, панически боится пауков, хвастун, суеверный, сладкоежка.
8. **Экономика**: 4 ценовые категории (еда / снаряжение / редкое / жильё-таверна) × город; покупка +0.5% (потолок ×1.8), возврат к базису 2%/тик, война ×1.4; агрегация влияния героев √(n/10).
